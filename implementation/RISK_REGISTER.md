| R-010 | The main JavaScript asset is 1,091,572 B / 273,498 B gzip after P4-05, above Vite's visible 500 kB warning; lazy Project, live My Work and Gate routes are 74,308 / 17,458, 11,763 / 3,936 and 57,650 / 13,716 B raw/gzip. | Later shared catalogs and business modules could worsen startup and interaction performance. | Keep the warning enabled, measure every vertical slice, retain route/data-boundary code splitting, and perform a dedicated shared-shell/catalog loading review before production release. | Open — Phase 4 growth is measured debt; the warning and threshold remain unchanged |

| R-012 | Prototype or unavailable notification, integration, telemetry and delivery states can be overclaimed as live service behavior. | False readiness, missed integration faults or invalid performance/localization conclusions. | Preserve explicit unavailable/prototype states and trace statuses; use the strict live Project/My Work BFF, server-resolved Due time zone and distinct System time zone, while leaving notification, integration-exception, telemetry ingestion and delivery to their owning phases. | Open — Project and My Work/time-zone boundaries are proven; remaining services stay explicitly bounded |
| R-013 | Pack trace allocation can be read as putting portfolio, portals, notifications and ERP-owned cost into Phase 4 although controller Phase 4/M3 is Project and Gate. | Scope creep or guessed ERP behavior could enter the first business slice. | Use the `P4-00` requirement anchor and trace remap; deliver ERP creation/cost in Phase 8 and portfolio/portal/notification extensions in Phase 9 while preserving IDs. | Mitigated — Phase 4 anchor passed 2026-07-22 |
| R-014 | A session-language mutation could bypass CSRF, fail before the domain error boundary, or leave a partial preference update while returning a non-success response. | Cross-site preference changes, raw Frappe errors, false retry semantics, or inconsistent session state. | Deliver the CSRF token only through authenticated no-store bootstrap, strip caller-supplied browser tokens, require the trusted token on `PUT`, normalize pre-handler malformed/CSRF failures to Problem Details, validate exact fields, roll back every non-2xx domain result, and preserve the original request locale until save plus cache invalidation succeed. | Mitigated — 58 Python tests, 110 frontend tests, cache-failure rollback/request-locale proof, and loopback missing/wrong-CSRF, malformed/field, unchanged-state, trace, and cleanup checks passed 2026-07-22 |
| R-015 | Prototype telemetry could accept arbitrary routes or identifiers and leak object/customer context. | Privacy breach or misleading operating evidence. | Restrict name, outcome, timestamp, duration, context-switch count, and route to finite validated values; reject query, hash, identifier, traversal, encoded, and non-finite variants; keep the recorder in memory only. | Mitigated for the Phase 3 prototype — unit validation passed; no live ingestion or durable metric is claimed |
| R-016 | Missing production numbering, template, RACI/approval, WorkItem lifecycle, health, exception, invalidation and Project lifecycle policies could be disguised as product defaults. | Incorrect approvals, false health, invalid Gate decisions or incompatible production data. | Keep rules versioned and fail closed when absent; install no production template/control policy; use clearly synthetic acceptance fixtures; maintain every recorded Class-B hold in the Phase 4 anchor and `REQUIRED_INPUTS.md`. | Open external — scoped; the generic versioned Project/Gate/control infrastructure passed Phase 4 without inventing production rules |
| R-017 | Concurrent Project retries, duplicate business codes, partial template instantiation, standalone child mutation, or tenant/IDOR access could corrupt or disclose the first live aggregate. | Duplicate or incomplete Projects, rewritten history, or cross-project/cross-tenant disclosure. | Use tenant-scoped business-code reservation, first-write idempotency with rollback/reload on races, one atomic Project/Gate transaction, exact immutable template snapshots, guarded child/history DocTypes, strict CSRF/BFF fields, fail-closed per-Site tenant configuration, owner/System Manager authorization, audit and trace IDs. | Mitigated for P4-01 — domain contract permission concurrency migration and real Frappe runtime checks passed 2026-07-23 |
| R-018 | A Domain WorkItem cursor could be forged, validated before Project authorization, or cause a read request to auto-provision Site configuration; related records could share a Project ID but belong to another tenant. | Pagination manipulation, object-existence disclosure, unexpected configuration mutation, or cross-tenant association. | Sign every cursor field with an existing Site-bound domain-separated key, authorize before key/shape/signature checks, fail 503 without querying or writing when the key is unavailable, and compare both Project and tenant on tenant-bearing identities and references. | Mitigated for P4-02 — affected API/repository tests and fresh real Frappe runtime passed 2026-07-23 |
