| R-010 | The main JavaScript asset is 881.93 kB minified / 222.77 kB gzip after P4-03, above Vite's visible 500 kB warning; the lazy Gate route is 11.64 kB / 3.63 kB gzip. | Later live data access, shared catalogs, and business modules could worsen startup and interaction performance. | Keep the warning enabled, measure every vertical slice, retain route/data-boundary code splitting, and perform a dedicated shared-shell/catalog loading review before Phase 4 exits. | Open — P4-03 growth is measured debt and the threshold remains unchanged |
| R-011 | Phase 3 business UAT and provenance-backed sanitized representative data are unavailable. | Technical fixtures could be mistaken for accepted usability or real operational evidence. | Keep acceptance at `TECHNICAL_PASS_PENDING_UAT` after the technical release gate; label fixtures, use the unsigned UAT script, and request all external evidence only through `REQUIRED_INPUTS.md`. | Open external — scoped; not a global blocker |
| R-012 | Prototype Worklist transport, zero-notification state, UTC rendering, in-memory telemetry and renderer-only non-screen copy can be overclaimed as live service behavior. | False readiness, missed integration faults or invalid performance/localization conclusions. | Preserve explicit unavailable/prototype states and trace statuses; the Project cockpit is now live through its strict BFF while Worklist, notification, timezone, telemetry and delivery still require evidence in their owning phases. | Open — live Project boundary proven; remaining services stay explicitly bounded |
| R-013 | Pack trace allocation can be read as putting portfolio, portals, notifications and ERP-owned cost into Phase 4 although controller Phase 4/M3 is Project and Gate. | Scope creep or guessed ERP behavior could enter the first business slice. | Use the `P4-00` requirement anchor and trace remap; deliver ERP creation/cost in Phase 8 and portfolio/portal/notification extensions in Phase 9 while preserving IDs. | Mitigated — Phase 4 anchor passed 2026-07-22 |
| R-014 | A session-language mutation could bypass CSRF, fail before the domain error boundary, or leave a partial preference update while returning a non-success response. | Cross-site preference changes, raw Frappe errors, false retry semantics, or inconsistent session state. | Deliver the CSRF token only through authenticated no-store bootstrap, strip caller-supplied browser tokens, require the trusted token on `PUT`, normalize pre-handler malformed/CSRF failures to Problem Details, validate exact fields, roll back every non-2xx domain result, and preserve the original request locale until save plus cache invalidation succeed. | Mitigated — 58 Python tests, 110 frontend tests, cache-failure rollback/request-locale proof, and loopback missing/wrong-CSRF, malformed/field, unchanged-state, trace, and cleanup checks passed 2026-07-22 |
| R-015 | Prototype telemetry could accept arbitrary routes or identifiers and leak object/customer context. | Privacy breach or misleading operating evidence. | Restrict name, outcome, timestamp, duration, context-switch count, and route to finite validated values; reject query, hash, identifier, traversal, encoded, and non-finite variants; keep the recorder in memory only. | Mitigated for the Phase 3 prototype — unit validation passed; no live ingestion or durable metric is claimed |
| R-016 | Missing production numbering, template, RACI/approval, WorkItem lifecycle, health, exception, invalidation and Project lifecycle policies could be disguised as product defaults. | Incorrect approvals, false health, invalid Gate decisions or incompatible production data. | Keep rules versioned and fail closed when absent; install no production template; use clearly synthetic acceptance fixtures; maintain every recorded Class-B hold in the Phase 4 anchor and `REQUIRED_INPUTS.md`. | Open external — scoped; generic infrastructure may continue |
| R-017 | Concurrent Project retries, duplicate business codes, partial template instantiation, standalone child mutation, or tenant/IDOR access could corrupt or disclose the first live aggregate. | Duplicate or incomplete Projects, rewritten history, or cross-project/cross-tenant disclosure. | Use tenant-scoped business-code reservation, first-write idempotency with rollback/reload on races, one atomic Project/Gate transaction, exact immutable template snapshots, guarded child/history DocTypes, strict CSRF/BFF fields, fail-closed per-Site tenant configuration, owner/System Manager authorization, audit and trace IDs. | Mitigated for P4-01 — domain contract permission concurrency migration and real Frappe runtime checks passed 2026-07-23 |
