# Risk Register

| ID | Risk | Impact | Mitigation | Status |
|---|---|---|---|---|
| R-001 | A fresh Codespace entered Alpine recovery because the target Dockerfile inherited a Yarn APT source with an unavailable signing key. | Target-container creation and Phase 3 were blocked. | Sanitize both `/etc/apt/sources.list` and `/etc/apt/sources.list.d/*yarn*` before APT refresh, lock/verify all remote artifacts, then verify the rebuilt target dynamically. | Resolved — fresh target and dynamic gate passed 2026-07-21 |
| R-002 | Large V1.2 scope can hide trace gaps. | P0/P1 omission | Machine-readable requirement trace and per-phase gates | Open |
| R-003 | Siemens component defaults may violate square/neutral baseline. | UI gate failure | Keep Siemens imports behind the local adapter, generate company tokens, reject raw geometry/style violations and run computed-style plus exact zero-tolerance visual assertions. | Mitigated — 129/129 regeneration, 129/129 clean zero-difference comparison, and six-image manual review passed 2026-07-22 |
| R-004 | Translation fallback can mask missing Chinese. | Language gate failure | Require direct complete `zh` and `zh-TW` catalogs, missing/placeholder/context/terminology checks, DOM/shadow-root mixed-language scans and normal-user runtime proof. | Mitigated — 556 direct entries per locale, Administrator isolation and three-locale static/runtime gates passed 2026-07-22 |
| R-005 | ERP retry/replay can duplicate execution. | External data corruption | Idempotency, inbox/outbox, expected version, reconciliation and fault tests | Open |
| R-006 | No production ERP access for final activation. | External go-live dependency | Mock plus sandbox-ready adapter and activation runbook | Accepted external |
| R-007 | A Codespaces clone may retain generated Git LFS hooks even though the repository has no LFS attributes or pointer objects. | Push fails when the unused `git-lfs` binary is absent. | Verify attributes and reachable history before removing only clone-local generated hooks; require approved attributes and reproducible installation before any future LFS adoption. | Mitigated — current clone residue removed |
| R-008 | A valid immutable base image can still reference time-sensitive external package repositories whose signing configuration later expires. | Reproducible container creation can fail before Feature or post-create execution. | Remove the unused Yarn APT source from both supported locations, forbid signature/trust bypasses and validate base/Feature/tool artifacts against official registries before delivery. | Mitigated — repaired build and dynamic proof passed |
| R-009 | Privilege elevation can sanitize the Node Feature PATH during lifecycle commands. | npm CLIs with `/usr/bin/env node` fail even though Node is installed for the remote user. | Install fixed npm tools through the verified writable remote-user prefix; statically reject `sudo npm`; rerun the exact lifecycle script in a fresh target. | Resolved in repair round 4 |
| R-010 | The Phase 3 main JavaScript asset is 761.17 kB minified, above Vite's visible 500 kB warning. | Later live data access and business modules could worsen startup and interaction performance. | Keep the warning enabled, measure the baseline, and require route/data-boundary code splitting plus performance re-evaluation as Phase 4 adds real modules. | Open — measured debt, not hidden by a raised threshold |
| R-011 | Phase 3 business UAT and provenance-backed sanitized representative data are unavailable. | Technical fixtures could be mistaken for accepted usability or real operational evidence. | Keep acceptance at `TECHNICAL_PASS_PENDING_UAT` after the technical release gate; label fixtures, use the unsigned UAT script, and request all external evidence only through `REQUIRED_INPUTS.md`. | Open external — scoped; not a global blocker |
| R-012 | Prototype Worklist transport, zero-notification state, UTC rendering, in-memory telemetry and renderer-only non-screen copy can be overclaimed as live service behavior. | False readiness, missed integration faults or invalid performance/localization conclusions. | Preserve explicit unavailable/prototype states and trace statuses; require live BFF, notification, timezone, telemetry and delivery evidence in their owning phases. | Open — bounded and documented |
| R-013 | Pack trace allocation can be read as putting portfolio, portals, notifications and ERP-owned cost into Phase 4 although controller Phase 4/M3 is Project and Gate. | Scope creep or guessed ERP behavior could enter the first business slice. | Make `P4-00` a requirement anchor that resolves the mapping before code; hold only ambiguous rows and continue unambiguous NPI-owned work. | Active — scoped to Phase 4 planning |
| R-014 | A session-language mutation could bypass CSRF, fail before the domain error boundary, or leave a partial preference update while returning a non-success response. | Cross-site preference changes, raw Frappe errors, false retry semantics, or inconsistent session state. | Deliver the CSRF token only through authenticated no-store bootstrap, strip caller-supplied browser tokens, require the trusted token on `PUT`, normalize pre-handler malformed/CSRF failures to Problem Details, validate exact fields, roll back every non-2xx domain result, and preserve the original request locale until save plus cache invalidation succeed. | Mitigated — 58 Python tests, 110 frontend tests, cache-failure rollback/request-locale proof, and loopback missing/wrong-CSRF, malformed/field, unchanged-state, trace, and cleanup checks passed 2026-07-22 |
| R-015 | Prototype telemetry could accept arbitrary routes or identifiers and leak object/customer context. | Privacy breach or misleading operating evidence. | Restrict name, outcome, timestamp, duration, context-switch count, and route to finite validated values; reject query, hash, identifier, traversal, encoded, and non-finite variants; keep the recorder in memory only. | Mitigated for the Phase 3 prototype — unit validation passed; no live ingestion or durable metric is claimed |
