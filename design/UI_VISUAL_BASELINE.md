# Siemens iX Classic 工业 UI 视觉基线

## 1. 唯一基线

NPI One 的终端界面以 **Siemens Industrial Experience（iX）Classic Light** 与经典西门子工程应用的工作方式作为唯一视觉和布局基线：稳定应用框架、矩形导航、紧凑工具条、对象树、表格、分栏、属性检查器、工作流和明确边界。

这是一套产品结构与交互基线，不是品牌复制：
- React 端默认通过本地适配层使用 `@siemens/ix`、`@siemens/ix-react` 和 `@siemens/ix-icons`；
- 根节点默认采用 `data-ix-theme="classic"` 与 `data-ix-color-schema="light"`；
- 使用公司名称、公司主色和系统字体；
- 不使用 Siemens 商标、logo、专有字体或仅限 Siemens 官方产品的 Corporate Brand Theme；
- 任何替换 iX 的提案必须有事实证据、ADR、迁移方案与人工批准，不能由开发人员自行改用另一套组件库。

## 2. 视觉配比

- 中性色面积：85%–90%。
- 单一主色面积：5%–10%。
- 成功/警告/错误等语义色合计：小于 5%，只做小面积状态表达。
- 普通圆角：0px；输入、按钮和对话框在确有可用性需要时最多 2px。
- 圆形：只用于头像、单选框、状态灯、进度节点等具有圆形语义的对象。
- 页面/面板阴影：0；浮层允许一层轻微阴影。
- 表格行高：32px 紧凑、36px 默认。
- 控件高度：32px 紧凑、36px 默认。
- 基础间距：4px / 8px；跨区间距 16px / 24px。

## 3. 页面骨架

```text
┌──────────────────────────── 48px 顶部应用栏 ────────────────────────────┐
├──── 216px 域导航 ────┬──────────────── 页面工具条 40px ───────────────┤
│                      ├────────────── 对象头 64–88px ───────────────────┤
│                      │  对象树/列表  │   主工作区   │  检查器 340px     │
│                      │  可调整宽度    │   可调整宽度 │  可停靠/折叠       │
│                      ├─────────────────────────────────────────────────┤
└──────────────────────┴──────────── 可选状态栏 24px ────────────────────┘
```

核心区域不得随页面任意漂移。用户在项目、模具、试模、设计基线和执行请求之间切换时，导航、工具条、对象头、主动作和检查器的位置保持稳定。

## 4. iX 组件映射原则

优先映射 iX 的 Application、Application Header、Application Menu、Content Header、Breadcrumb、Tabs、Tree、Workflow、Panes、Form、Message Bar、Progress、Table/数据网格等公开组件模式。业务页面只依赖 `frontend/src/ui-adapters/` 中的本地组件接口，不在领域目录直接散布第三方组件 API。

- 导航：矩形整行命中，左侧 3–4px 主色选中条；无胶囊。
- 按钮：矩形；主按钮实色，次按钮边框或文本；同一上下文最多一个视觉主按钮。
- 状态：文字 + 小图标/形状 + 可选左侧状态线；不使用彩色药丸作为主要表达。
- 面板：白底 + 1px 边框；标题栏浅灰；无阴影。
- 表格：固定表头、细网格、列对齐、选中行使用浅主色底；支持键盘与保存视图。
- 工作流：使用矩形阶段轨、步骤表或小状态灯；不得使用大号彩色圆点装饰。
- 对话框：仅用于阻断、高风险确认或短输入；复杂工作使用停靠面板或独立工作区。
- 图表：只有能回答明确业务问题时才使用，并提供可读取的数据表或摘要。

## 5. 禁止模式

出现任一项即为 UI 发布阻断：
- 两种以上非语义强调色同时主导页面；
- KPI 卡片使用多种背景色；
- 业务页普遍使用 8px、12px 或更大圆角；
- 面板依赖阴影区分层级；
- 渐变、玻璃拟态、霓虹、悬浮胶囊导航或装饰插画主导；
- 首屏大于 25% 空白，同时关键工程数据仍需滚动查看；
- 对象树、表格、属性检查器或工作流被卡片墙替代；
- Frappe Desk 导航、原始 DocType 表单或低代码元数据直接暴露给普通用户；
- 组件库默认样式破坏本文件的色彩、圆角、密度、边框或层级约束；
- 页面看起来像营销型 SaaS，而不是经典工程工作台。

## 6. 截图与回归验收

每个核心页面必须提供以下证据：
- 1366×768、1440×900 和 1920×1080；1440×900 是 additive V1.2
  reconciliation target，不追溯否定既有 1366×768 Gate 证据；
- 浏览器 100%、125% 和 150% 缩放；
- 英文、简体中文和繁体中文；
- 正常、加载、空数据、只读、无权限、错误、冲突、异步处理中和部分成功状态；
- token 审计：非语义颜色数量、最大普通圆角、阴影、行高、控件高；
- 与 `specs/ui/` 基准图的视觉回归或人工差异说明。
