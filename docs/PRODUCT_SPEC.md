# 产品规格 — NPI One

版本：V1.2
状态：Codex 实施基线
适用业务：客户来模、按图新制模具、改模/工程变更、试模、NPI 与量产移交

## 1. 产品问题

现有 ERPNext 已承载模具、质量、变更和文件等业务，但工程开发过程仍容易被拆成大量相互独立的单据。使用者需要记忆模块、DocType 和菜单，讨论、任务、版本、试模和门禁上下文被打散，同部门及小范围跨部门协作效率低。

NPI One 不是再造一套 ERP，而是把工程开发对象聚合成专业工作空间：
- 项目是最高协作上下文；
- Tooling、设计基线、试模轮次、阶段门和变更是一级对象；
- 任务、问题、行动、决策、文档和 ERP 执行都在对象上下文内出现；
- 正式交易由 ERPNext 执行并回写真实状态。

## 2. 用户与核心任务

| 角色 | 首要任务 | 默认入口 |
|---|---|---|
| 项目经理 | 看全局、推进阶段门、处理阻断、协调负责人 | 我的工作、项目驾驶舱、组合看板 |
| 产品/模具设计 | 管输入、版本、评审、基线和设计问题 | 设计工作区、模具开发驾驶舱 |
| 模具工程/供应商管理 | 跟踪方案、制造里程碑、成本、试模和验收 | 模具开发驾驶舱 |
| 工艺工程 | 计划试模、记录参数、比较轮次、固化窗口 | 试模工作区 |
| 质量 | 检验计划、结果、缺陷、样件/客户批准 | 试模工作区、NPI 移交 |
| 采购 | 在 ERPNext 执行 PO/收货；在项目上下文查看需求与状态 | ERP 执行面板、ERPNext |
| 生产/设备 | 确认机台、产能、作业文件、培训和移交 | NPI 移交 |
| 管理层 | 看组合健康度、SOP 风险、Tooling 周期和成本 | 组合看板 |
| 管理员/支持 | 配置模板、权限、集成与异常回放 | 管理中心/Frappe Desk |

## 3. 信息架构

一级导航不按 DocType 罗列，固定为：
1. **我的工作**：个人待办、审批、阻断、决策请求、同步异常、即将到期。
2. **项目组合**：项目列表/时间轴/健康度/目标 SOP/阶段/客户。
3. **项目**：项目驾驶舱和对象树。
4. **Tooling**：跨项目模具开发与试模状态。
5. **设计与基线**：文档、版本、设计评审、发布包、EBOM。
6. **试模与 NPI**：试模计划/轮次、样件、质量证据、就绪和移交。
7. **变更**：影响分析、任务包、重新验证和生效。
8. **分析**：角色化指标和异常趋势。
9. **管理**：模板、字典、权限、集成、审计；仅授权用户可见。

## 4. 项目生命周期

- G0 可行性：客户输入完整性、技术/产能/商业风险。
- G1 立项：章程、团队、责任界面、预算、目标 SOP 和基线计划。
- G2 DFM/设计冻结：输入版本、产品/模具方案、关键假设和基线。
- G3 模具启动/接收：新制模具释放制造；客户来模完成接收/差异/授权。
- G4 试模迭代：T0–Tn、参数、样件、缺陷和整改。
- G5 样件/质量批准：内部与客户批准、偏差有效期。
- G6 试产/量产就绪：能力、文件、培训、供应链、质量和维护。
- G7 SOP 移交/结项：正式移交、遗留项、观察期和经验复盘。

阶段门通过时必须冻结证据快照。关键输入改变后，系统按规则触发条件失效或复审；不得覆盖历史批准。

## 5. 项目驾驶舱

项目驾驶舱是项目用户的主要工作页面，不是报表首页。必须包含：
- 动态对象头：项目、客户、产品、目标 SOP、当前 Gate、健康度、PM、正式/草稿状态；
- 阶段轨：G0–G7 的状态、到期、阻断、待审批；
- 下一最佳行动：按权限与优先级显示一个主动作；
- 关键指标：进度、成本、Tooling、试模轮次、NPI 就绪、同步异常；
- 对象树：产品/设计基线/Tooling/试模/样件/变更/ERP 对象；
- 工作区标签：概览、计划、设计、Tooling、试模、NPI、变更、文件、活动；
- 右侧上下文抽屉：评论、行动、决策、关联、活动，不离开当前页面；
- 风险/问题/行动/决策统一列表；
- ERP 执行状态与可进入的正式单据链接。

## 6. 我的工作

统一工作队列必须包含不同对象类型但统一字段：
- 类型、标题、项目/Tooling/试模上下文；
- 为什么轮到我；
- 截止日/逾期、严重度、阻断属性；
- 需要的动作；
- 来源系统与同步状态；
- 快速处理或进入上下文。

支持保存视图：今天、逾期、待审批、被我阻断、等待他人、接口异常、我负责的项目。批量操作仅用于低风险且同构动作；审批、发布、阶段门等不得用无影响摘要的盲目批量操作。

## 7. 功能域

### 7.1 项目与组合
模板、章程、团队/RACI、里程碑、依赖、健康度、风险、问题、行动、决策、会议、基线和复盘。

### 7.2 阶段门与交付物
模板、必交项、证据、阻断、并行/顺序会签、条件通过、豁免、快照、复审、到期升级。

### 7.3 设计与基线
客户输入、DFM、产品/模具设计、文档编号、修订、评审、发布、替代、哈希、发布包、EBOM 工作版本/差异和 ERP 发布请求。

### 7.4 Tooling
客户来模、新制模具、改模/复制；规格、所有权、穴位、设计版本、制造/供应商、预算与 ERP PO 状态、试模、缺陷、验收、保修和 ERP 资产移交。

### 7.5 试模
计划、资源、输入版本锁、机台/材料/环境/参数、穴号样件、图片/测量、缺陷/根因/措施、轮次结论、T0–Tn 比较和下一轮任务。

### 7.6 NPI
清单、证据、材料/色号/包装、参数窗口、质量/客户批准、产能/Run-at-rate、试产、文件/培训/供应链、就绪度、阻断项、量产移交和观察期。

### 7.7 变更
引用 ERPNext 正式 ECR/ECO/ECN；在 NPI One 完成工程影响分析、受影响对象、任务包、改模/试模/质量验证、门禁复审和现场切换证据。

### 7.8 协作
上下文评论、@、关注、活动时间线、问题/行动/决策、受控外部协作和到期/升级通知。界面语言遵守英文源语言 + Frappe 翻译目录。

## 8. 体验验收指标

- 视觉与布局以 Siemens iX / 经典西门子工程软件为唯一主要参考；不得退化为 Frappe Desk 或消费级 SaaS。
- 85%–90% 界面使用中性色；主色固定为工业深青；语义色仅做小面积辅助。
- 普通面板、按钮、输入和标签默认 0–2px 圆角；页面面板默认无阴影。
- 首页和驾驶舱优先表格、树、分栏和检查器，不使用彩色 KPI 卡片墙。
- 英文为唯一源语言；中文由 Frappe 翻译目录产生。除词表术语、业务数据、编码和单位外，同一页面不得混用语言。
- 至少 80% 的高频任务可从“我的工作”或“项目驾驶舱”开始并完成。
- 高频任务不超过 2 次上下文切换；不得依赖用户记住 DocType 名。
- 普通业务用户的关键流程不进入 Frappe Desk。
- 页面最多一个视觉主动作；次要动作进入明确菜单。
- 每个远程动作都有 loading、排队/处理中、成功、失败和可重试反馈。
- 所有核心页面具备空、无权限、只读、冲突和部分数据不可用状态。
- 状态不能只依赖颜色；使用文本、图标和语义说明。
- 项目、Tooling、试模和 Gate 能在上下文内评论和创建行动，不强制跳页。
- 试模/Gate/发布/移交均可还原确切输入版本和证据。

## 9. MVP 不做

- 不在 UI 中复制 ERPNext 的采购、库存、生产、财务完整功能；
- 不做任意可配置低代码页面生成器；
- 不做 CAD 编辑器；
- 不为少数特例破坏全局状态机；
- 不一次性接入所有外部系统；
- 不把“表单字段多”当成功标准；
- 不做彩色、过度圆角、渐变或营销化视觉；
- 不在前端另建与 Frappe 无关的翻译体系。
