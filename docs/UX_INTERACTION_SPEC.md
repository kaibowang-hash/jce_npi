# UX 与交互规格

## 1. 设计意图与唯一参考基线

NPI One 的终端界面必须以 **Siemens Industrial Experience (iX) 与经典西门子工程软件**为唯一主要参考：克制、方正、稳定、高信息密度、对象和工作流优先。Frappe Desk、其他企业设计系统、消费级 SaaS、营销网站和移动应用卡片风格均不得作为视觉基线。

采用 Siemens 参考时，使用公开组件模式、结构和交互原则；产品使用公司自有名称、主色、图标适配和字体，不复制 Siemens logo、专有字体或受限品牌资产。

核心原则是 **Object-first, Workflow-aware, Context-preserving**：
- 先让用户确认“我在处理哪个项目/模具/试模/版本”；
- 再让用户看状态、阻断、差异和下一动作；
- 只有需要时才展开字段、关系和历史；
- 任何跳转都保留返回上下文；
- 视觉层级服务工程判断，不服务装饰。

## 2. 视觉语言硬规范

### 2.1 色彩
- 使用一个工业深青色主色，具体值见 `design/design-tokens.json`。
- 85%–90% 的界面面积使用白、浅灰、深灰和边框中性色；主色用于选中、主动作、焦点和少量关键强调。
- 成功、警告、危险为语义色，只用于小面积图标、文字、左侧状态条或低饱和浅底；不得把每种对象做成不同彩色卡片。
- 信息状态复用主色，不另引入紫色、亮蓝、粉色等装饰色。
- 禁止渐变、霓虹、玻璃拟态、彩虹标签、彩色 KPI 卡片墙和大面积品牌色背景。

### 2.2 形状、边界与层级
- 普通按钮、输入框、面板、表格、标签默认 0–2px 圆角。
- 圆形只允许头像、单选框、进度节点、状态灯等本身具有圆形语义的元素。
- 禁止 8px、12px 或更大圆角在业务界面普遍出现；禁止悬浮胶囊式导航和大片圆角卡片。
- 主要层级通过 1px 边框、表头底色、分隔线、缩进、选中条和列宽建立。
- 页面默认无阴影；弹出菜单、对话框等浮层可有轻微阴影。禁止厚重阴影和漂浮卡片感。

### 2.3 排版与密度
- 使用公司批准的系统无衬线字体；不得假设可使用 Siemens 专有字体。
- 正文默认 14px，表格/树可 13–14px；对象标题通常 20–24px，不使用营销式 36–48px 巨型标题。
- 紧凑行高 32px，默认行高 36px；工具条和控件高度 32–36px。
- 优先使用表格、树表、字段组、分割面板、工具条和状态栏；减少大面积留白。
- 数据密集不等于拥挤：保持 4/8px 基础间距、清晰列对齐和键盘焦点。

### 2.4 禁止的视觉模式
- 多彩统计卡片或每个状态一种背景色；
- 主页英雄横幅、宣传插画、装饰性空状态插画；
- 浮动胶囊导航、圆角卡片瀑布流；
- 用大图表代替可操作清单；
- 仅为“现代感”引入动画、渐变或玻璃效果；
- 直接套用 Frappe Desk 主题后称为专业工程软件。

### 2.5 图标与紧凑动作
- 图标必须通过 `frontend/src/ui-adapters/` 的本地适配层映射；领域页面不得
  直接导入第三方图标 API、品牌图标或另建图标体系。
- 熟悉、低风险、上下文明确的次级动作可采用 icon-first；仅图标动作必须
  有翻译后的可访问名称和 tooltip，并覆盖键盘、焦点、活动、禁用和无
  hover 场景。
- 高风险、不可逆、主动作或含义可能混淆的动作必须保留可见文字；颜色和
  图标不能成为唯一含义。
- 可参考 GitHub 的紧凑 overflow、inline 和 sidebar 微交互，但 Siemens
  iX Classic/经典工程布局仍是唯一主要基线；不得复制 GitHub 品牌、颜色，
  也不得引入未经批准的 Primer/Octicons 依赖。

## 3. 经典工程应用布局

### 3.1 固定区域
- **顶部应用栏（约 48px）**：产品/环境、当前上下文、全局搜索、通知、帮助、用户。位置固定，动作克制。
- **左侧域导航（约 208–224px）**：一级域、当前域、未处理数量；采用矩形选中行和 3–4px 主色选中条，不使用圆角胶囊。
- **页面工具条（约 36–40px）**：面包屑、保存视图、过滤、刷新、列设置、上下文动作。
- **对象头（约 64–88px）**：编号、名称、修订、状态、来源、同步、关键日期和一个主动作；不得做成巨型卡片。
- **中央工作区**：全宽使用；支持对象树、树表、表格、比较区和可调整分栏。
- **右侧检查器（约 320–360px，可调）**：属性、评论、行动、历史和关联，优先停靠而非浮动弹窗。
- **底部状态栏（可选 24px）**：环境、保存/同步、选中数、后台操作状态和 trace 入口。

左侧域导航支持完整（图标+标签）和折叠（仅图标）模式。折叠状态按用户
保存，响应式可自动折叠；tooltip、活动态、键盘访问和当前项目上下文不得
丢失。

### 3.2 环境防错
测试、预生产和生产环境必须有持续可见的环境文字标签。生产高风险动作使用明确的生产环境文案与影响复核，但不得仅靠颜色区分。

## 4. 页面模式

### 4.1 工程工作清单
适用“我的工作”、项目组合、Tooling 列表、试模列表。
- 紧凑、可读、带网格和固定表头的数据表；
- 保存视图、列配置、过滤器、分组、排序；
- 列头边缘拖动调整宽度，双击自适应，支持 min/max、固定列、横向滚动和
  reset；按用户+视图+表 schema version 保存，并提供键盘替代；
- 行打开详情或在 split-view 中预览；
- 状态、来源、版本和下一动作字段固定；
- 大数据采用服务端分页/虚拟化；
- 批量动作显示适用行数、跳过原因和影响；
- 禁止用彩色卡片替代表格。

### 4.2 工程对象页
适用项目、Tooling、试模轮次、设计基线、变更。
- 紧凑对象头；
- 阻断与下一动作优先；
- 章节锚点或矩形标签页；
- 一个主动作；
- 重要侧边信息放在停靠式检查器；
- 关键属性以字段组或表格展示，不堆卡片。

### 4.3 工程工作区
适用设计评审、阶段门评审、试模和 NPI 移交。
- 左侧证据/对象树，中间工作内容，右侧审阅/行动；
- 分栏可调整宽度并记住用户偏好；
- 从实际分栏边界拖动；边界双击重置，折叠按钮集成在边缘/标题，且提供
  键盘调整；
- 保持选中对象和滚动位置；
- 支持并排比较、差异高亮和版本锁；
- 提交前显示缺失、冲突、版本变化和影响。

## 5. 核心页面

### 5.1 我的工作
顶部使用紧凑摘要条或过滤标签，不使用五颜六色的 KPI 卡。工作表每条事项回答：
- 这是什么；
- 为什么是我；
- 有何影响；
- 下一动作；
- 最晚何时；
- 在哪里产生。

当前已批准默认仍遵循 `FR-UX-008` 的上下文检查器。My Work 专用的行内
展开 + drawer/Object Page fallback 是 `FR-UX-042`/DR-REC-001 的待决
页面修订；批准前不得静默替换全局 inspector pattern。

### 5.2 项目驾驶舱
默认打开概览，下一行动和阻断优先于图表。项目结构、阶段门、模具开发、试模、NPI 和 ERPNext 执行在同一项目上下文下切换。关键指标采用紧凑字段带/表格，不做彩色卡片墙。

### 5.3 阶段门评审室
三栏：
1. 交付物与证据树；
2. 选中证据的版本/预览/审阅；
3. 阻断、意见、会签和决策。

“通过”前展示：
- 缺失/过期/未批准证据；
- 未关闭阻断；
- 自上次评审后变化的输入；
- 通过后锁定内容；
- 受影响的后续 Gate。

### 5.4 模具开发驾驶舱
对象头显示模具类型、所有权、穴数、当前版本、供应商、目标/实际日期、成本、当前试模轮次、ERP 资产状态。下方采用矩形生命周期轨或状态表，覆盖“设计—制造—试模—验收—ERP 资产”。

### 5.5 试模工作区
试模轮次是独立对象：
- 计划与资源；
- 锁定的产品/模具/设计/材料版本；
- 参数组与实际值；
- 样件/穴号；
- 缺陷和行动；
- 质量结果/客户反馈；
- 结论和下一轮；
- 与前轮差异。

允许草稿自动保存，但正式提交必须显式确认并形成不可变快照。

### 5.6 ERP 执行面板
在项目对象旁展示：
- 要在 ERPNext 执行的动作；
- 输入数据摘要和字段主责；
- 校验结果；
- 执行请求状态；
- ERPNext 返回的正式编号/单据；
- 失败原因、重试/取消权限、trace ID。

用户不得看到“已提交”却误以为“ERP 已完成”。

## 6. 表单与编辑

- 分为摘要字段、必填字段和高级字段；使用字段组、表格和可折叠区，不使用卡片瀑布。
- 支持草稿、dirty 状态、离开保护和冲突检测。
- 服务器返回字段级错误和业务级错误。
- 对只读字段显示来源（ERPNext/NPI One/计算）和为什么不可改。
- 版本化对象需要“另存为新修订”，不得直接覆盖发布版本。
- 日期、金额、单位和时区统一格式；关键单位旁明确显示。
- 使用选择器展示编码 + 名称 + 状态，避免只显示内部 ID。
- 每个字段明确 required/optional、editable/read-only/conditional、来源、
  锁定原因、校验、单位和相关版本/生效状态。
- 附件控件提供清除、拖放和选择器，并显示类型/大小指导、上传/扫描/
  处理中/失败、注册后的精确修订/hash、权限和密级；私有原始 URL 不构成
  授权。

## 7. 高风险动作

下列动作至少使用 review step，而非简单“确定/取消”：
- Gate 通过/条件通过/重开；
- 文档/设计/EBOM 发布或替代；
- 创建/更新 ERPNext 正式对象；
- 试模正式结论；
- 模具验收和资产移交；
- 批量重试、回放或取消集成消息；
- 变更生效与关闭；
- 删除或作废。

Review step 要显示对象、版本、影响、权限、不可逆部分、失败处理和审计结果；必要时要求原因或二次身份确认。

## 8. 异步与错误

状态词内部值统一：
- `queued`
- `processing`
- `succeeded`
- `partially_succeeded`
- `failed_retryable`
- `failed_final`
- `cancelled`

用户看到的文字必须按当前语言完整翻译。错误信息必须包含：
- 用户能理解的原因；
- 哪一步失败；
- 数据是否已部分写入；
- 可采取动作；
- trace/request ID；
- 技术详情仅在授权详情中展开。

## 9. 可访问性与响应式

- 桌面为主要场景；平板支持现场查看、拍照、试模记录和批准。
- 关键流程保证键盘可操作、焦点可见、对话框焦点管理、表单标签关联。
- 状态用文字/图标/形状共同表达。
- 图表提供可读数据表或摘要。
- 不以 hover 作为唯一操作入口。
- 高密度表格支持 125%/150% 浏览器缩放。

## 10. 设计系统约束

- React 基线为 Siemens iX Classic Light：默认安装 `@siemens/ix`、`@siemens/ix-react`、`@siemens/ix-icons`，根节点设置 `data-ix-theme="classic"` 和 `data-ix-color-schema="light"`。如 M0 发现事实性阻断，必须通过 ADR 提出替代，不能静默换库。
- 不使用仅限 Siemens 官方产品的 Corporate Brand Theme，也不复制 Siemens logo、专有字体或品牌资产。
- `design/design-tokens.json` 是色彩、圆角、间距、密度、边框和阴影的唯一源；业务组件禁止硬编码。
- 第三方组件通过 `frontend/src/ui-adapters/` 封装，业务页面不得深度绑定 iX 具体 API。
- Siemens iX 组件默认样式如与本规格冲突，必须由 adapter/theme 收敛，不得以“组件默认”作为例外。
- 领域组件至少包括：ObjectHeader、SemanticStatus、GateTrack、SourceBadge、SyncBadge、ImpactReview、EvidencePanel、VersionPicker、WorkItemRow、LifecycleTrack、DockedInspector、TreeTable、OperationStatus。
- 图标只表达辅助含义，必须有标签或 tooltip。
- 所有用户文案遵守 `docs/LOCALIZATION_SPEC.md` 和 `contracts/terminology-allowlist.yaml`。

### 10.1 LaunchFlow 显示品牌

品牌开发只使用 `docs/Brand Asset/Brand Asset Instruction.csv` 与同目录
精确资产：

- white wordmark 用于暗背景，standard wordmark 用于亮背景；
- square icon 用作 favicon 与紧凑 platform/source identity；
- Loading 资产只用于 blank entry/start/full-page loading，不替代表格/
  对象 skeleton；
- Company LOGO 只用于 persistent website footer；
- `Core.png` 仅分配给 FR-BR-002/Phase 8/M7-09 的 JCE Core 显示身份，
  R1-02 不提前启用。

资产颜色是 logo 内部的窄范围例外，不改变工业深青 action/navigation
token。不得重画/改色资产、把 Company LOGO 当作 ERP/JCE icon，或从外部
寻找替代品牌。图标替代可见 source text 时仍提供当前语言的 accessible
name。`Core.png` 的后续显示适配不得改变稳定 `NPI_ONE`/`ERPNEXT` 代码、
内部 app 名和 `/api/npi/v1`。

## 11. 语言与翻译

- 英文是唯一源语言，中文通过 Frappe 翻译机制产生。
- 用户切换中文后，菜单、按钮、字段、帮助、状态、错误、通知、邮件和打印模板不得残留普通英文。
- 用户切换英文后不得残留普通中文。
- Tooling、NPI、DFM、EBOM、MBOM、SOP、ERPNext 等批准术语可按词表保留；客户名称、零件名称、文件名和编码属于业务数据，不计入 UI 混用。
- 缺少翻译在开发环境显示明显标记，在 CI 和生产发布中作为阻断。
- 详细规则见 `docs/LOCALIZATION_SPEC.md`。

## 12. M1 原型验收

M1 之后每个新增业务模块仍先提交可点击原型或完整 Storybook 状态，
覆盖正常、空、加载、只读、无权限、错误、冲突和异步处理，再进入完整
业务实现。R1 之前已经通过的 Gate 不追溯重开；对现有 checkpoint 的继续
开发只需为尚未实现的交互补齐原型证据。原型批准不构成状态机、权限、
数据主责或生产规则批准。

使用真实但脱敏的样例数据，完成至少 6 个可点击流程：
1. 从“我的工作”处理一个逾期 Gate 交付物；
2. 在项目驾驶舱定位阻断并创建行动；
3. 评审并释放一个 Tooling 设计修订；
4. 创建 T1 试模，继承 T0 并比较变更；
5. 提交模具验收并查看 ERP 资产执行请求；
6. G6 评审发现正式质量结果失败并阻断。

每个流程至少由项目经理、工程/模具、质量三类代表进行走查。除任务完成率、误操作、返回查找和用时外，还必须验证：
- 页面是否符合单主色、方正、扁平、高密度和稳定分栏；
- 是否出现彩色卡片墙、大圆角、强阴影或消费级装饰；
- 1366×768、1440×900、1920×1080、125% 和 150% 缩放下是否可用；
- 1440×900 下是否无需滚动即可看到对象上下文、主要动作、工作列表和
  属性区；
- 同一流程的英文和中文版本是否都完整、无普通语言混用；
- 术语译法是否与词表一致。

严重问题关闭后才进入 M2/M3。

## 13. 受控撤销

- 只有被版本化业务策略明确标记为低风险且尚未越过不可逆边界的动作，
  才显示限时撤销。
- 撤销是新的受权命令，不是客户端回滚假象；它重新检查 actor、权限、
  对象版本、后续引用和幂等身份并写审计。
- 发布、批准、外部执行、已被下游引用或策略未分类的动作不显示撤销，
  而是说明影响和 forward-correction/recovery 路径。
- 列表刷新、导航和超时不能把未知结果显示为已撤销。
